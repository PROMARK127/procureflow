# 問い合わせ対応

取引追跡画面に申請番号（PR-00001形式）または発注番号（PO-00001形式）を入力し、承認経路・見積・検収・請求・操作履歴を確認する。

| 症状 | 確認箇所 |
| --- | --- |
| 承認が進まない | 現在ラウンドの未処理ステップと部門、差戻し理由 |
| 発注できない | 承認状態、採用見積、承認額との比較、既存発注 |
| 商品を選べない | カタログの有効状態 |
| 検収できない | 発注の有無、検収済みか、発注数量と受領数量 |
| 支払が進まない | 請求、検収、数量一致、金額一致、支払状態 |

`BUSINESS_RULE` は現在の状態や担当、金額・数量を確認する。 `MASTER_DATA` は商品・仕入先・担当者のマスタ、`VALIDATION` は入力値とPINを確認する。`SYSTEM_ERROR` はVercel FunctionsログのDBエラーコード、環境変数の設定有無、Neonの接続状態、マイグレーションの適用結果を調べる。

DB調査ではまず `transactions` を申請IDまたは発注IDで絞る。承認は `approval_steps`、採否は `quotations`、作業日時と担当者は `audit_logs` を申請IDで参照する。秘密情報を問い合わせ記録に貼り付けない。
