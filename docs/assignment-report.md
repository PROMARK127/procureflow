# 課題レポート下書き

ProcureFlowは、架空の東都テクノロジー株式会社でIT備品の購入申請、承認、見積比較、発注、検収、請求照合、支払記録を追跡する購買管理デモである。画面の担当者切替で五つの役割の業務を確認できる。

Next.js、React、TypeScript、Tailwind CSSとPostgreSQLを使用した。実装はDBスキーマ・初期データ、トランザクション付きAPI、業務画面、検証コードの順に作った。依存取得時に実行環境のネットワーク権限でnpmがEACCESを返したため、許可付き実行とプロジェクト内のnpmキャッシュで再試行した。

学習上の論点は、申請時の単価を明細に保存する理由、承認ラウンドを残す理由、発注・検収・請求を別テーブルに分ける理由、行ロックと一意制約の役割である。支払では発注・検収・請求の三点照合が重要となる。

実運用には本人認証、ロール別・部門別・仕入先別の厳密な認可、監査ログの保全と閲覧制限、操作権限の厳密化が必要となる。部分検収後の追納と請求訂正も実務向けの追加論点である。

AIによる実作業は、要件の整理、実装、検証手順と提出資料の作成。本人記入欄には、操作して理解した購買業務、設計判断への意見、面談で説明する事例を記入する。

## 実行結果

- TypeScriptチェックとNext.jsの本番ビルドに成功。
- PostgreSQL互換の埋め込みテストで、初期データの再投入、段階承認、差戻し・再申請、却下、見積超過、数量超過、未検収、金額不一致、二重支払の拒否を検証。
- ローカルNext.js本番ビルドをテスト用のPostgreSQL接続で起動し、HTTP APIで申請から支払完了まで確認。PINなしの更新は403、同時発注2件は片方が200、もう片方が409。
- Marketplace規約への同意後もCLIは同意待ちを返した。Vercelダッシュボードで連携が登録された後、そのインストールを指定してNeon Freeのプロジェクト用DBを作成・接続した。本番APIがDB未接続で503を返したため、接続設定を反映して再デプロイした。
- Neon上でマイグレーションを再実行し、サンプル取引が6件のまま保持されることを確認した。
- 本番公開URLで未ログインのChromeからダッシュボードと発注番号検索を確認。HTTP検証では申請 PR-00007、発注 PO-00004 が支払完了に到達した。PINなしは403、同時発注は200と409を返した。
